# PDF Annotate: theoretical fastest times

- Run: 2026-09-14 11:28
- Logical CPUs: 16
- View assumed: 2000 x 1240 device pixels (a laptop window at 200% scaling)

## Hardware limits

| Operation on 64 MB of pixels | Time | Throughput |
| --- | ---: | ---: |
| Plain memory copy | 7.15 ms | 8948 MB/s |
| Bytes to egui colours (making a texture's image) | 13.7 ms | 4657 MB/s |

Every pass over a page's pixels -- copying it out of pdfium, making the texture, uploading it to the GPU -- is bounded by roughly the memory copy rate. Uploading goes through the graphics driver, typically at a similar rate.

## Startup

| Step | Now | Floor | Why |
| --- | ---: | ---: | --- |
| Check the unpacked pdfium.dll | 7.79 ms | ~0 | Hash it at build time, not every launch |
| Load pdfium.dll | 31.9 ms | 31.9 ms | Windows loading a 7 MB DLL. This copy was just written, so antivirus scans it on first load; the app's long-lived copy loads faster (about 10 ms in the benchmark) |
| Initialise pdfium | 1.22 ms | 1.22 ms | pdfium's own setup |
| First launch only: write the DLL out | 11.3 ms | 11.3 ms | Disk write of 7 MB |

### Saving

pdfium writing the whole unchanged document (5.1 MB): 75.0 ms. A full save can't be faster than this plus the disk write; an incremental save only writes what changed.

### Rendering in parallel processes

Each process renders every page once at fit width, all running at the same time.

| Processes | Wall time | Pages per second | Speed-up |
| ---: | ---: | ---: | ---: |
| 1 | 4.36 s | 68.8 | 1.0x |
| 2 | 4.97 s | 120.7 | 1.8x |
| 4 | 5.38 s | 223.1 | 3.2x |
| 8 | 6.34 s | 378.5 | 5.5x |
| 16 | 9.70 s | 494.9 | 7.2x |

Process start-up (binding pdfium, parsing the file) is included, which is why one process is slower than the per-page numbers above suggest.

### The UI thread, running the real app headless

| Frames | Layout median | Layout p95 | Tessellate median | Frame median | Frame worst | Textures arriving |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| Idle (pointer over the page) | 24 µs | 41 µs | 14 µs | 38 µs | 0.20 ms | 0 frames, largest 0 MB |
| Scrolling at 60 fps through the document | 0.13 ms | 0.16 ms | 50 µs | 0.18 ms | 0.74 ms | 15 frames, largest 20 MB |

A 60 Hz display allows 16.7 ms per frame for everything, including the GPU drawing it. Upload of arriving textures happens on top of these times, in the frame that shows them.
