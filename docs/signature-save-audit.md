# PDF signature/save safety audit

Scope: native implementation audit baseline and staged handoff, not a claim of signature validation.

## Deferred-inventory follow-up (correctness checked; performance unmeasured)

`worker::signature_hint()` now combines the checked native signature count with checked public `PdfDocument::form_type()` at count zero. Native signature counting only sees top-level direct `/FT /Sig`, so zero alone cannot exempt AcroForms with nested/inherited signatures. No-form/count-zero opens keep the no-parser/no-service fast path; unsupported/error categories stay Unknown. Ordinary supported forms may eventually resolve NoSignaturesDetected. A positive signature hint paired with zero structurally discovered Sig fields stays Unknown.

`src/signature_discovery.rs` owns PDFium-free bounded inventory and a lazy single latest-job service: one running job plus one replaceable pending job, cooperative cancellation, panic/error → Unknown, no busy-thread join during open/drop. Worker and UI stay Unknown while pending. A private `Arc<OnceLock<SignatureDiscovery>>` is set before the bound final reply is published; Save/SaveAs/Extract read this authority, not a UI/protocol-supplied result. Jobs use the immutable snapshot and generation/fingerprint; stale jobs are canceled and app reply checks remain in force.

`Reply::SignatureDiscovery { generation, file, discovery }` is final and may follow Highlights/rendering. Completed worker rendering releases analysis; optional `Request::StartSignatureAnalysis { generation, file }` only schedules the matching job, never supplies a result. The app also sends this scheduling-only request once per pending open after the first matching complete page/usable region reply, covering helpers; matching final discovery (including Unknown) ends scheduling. Native-zero immediate-final replies therefore do not schedule normal subsequent renders. Headless/no-render paths retain the 100 ms scheduling fallback. This bounds waiting for a render, not parser wall time: lopdf loading is noninterruptible, with byte/object/decompression/traversal limits and cancellation checks before/after load and during traversal. No per-frame polling, crypto or network was added.

Focused checks passed: `cargo test -j2 --locked --lib signature_discovery` (5 including the app stale-reply test) and `--lib worker::` (13). Integration/full-regression and renewed release performance gates remain pending. Cost is deferred, not eliminated: time-to-editable/analysis-ready must be measured separately, and Save timing must await actual final readiness. The synchronous release regression evidence in `docs/signature-performance.md` is preserved and is not a result for this follow-up.

## Synchronous first milestone status (historical; superseded above)

Implemented: checked `PdfSignatures::count()` at the existing worker open; `SignatureDiscovery::{NoSignaturesDetected, Present { count }, Unknown}`; sibling `Reply::SignatureDiscovery { generation, file, discovery }` immediately after `Opened`. **Test evidence corrected the initial count-only proposal: PDFium counts empty signature fields too.** Native zero retains the no-extra-parser path; positive counts trigger bounded strict lopdf AcroForm field/value inspection in `worker::hinted_signatures()`. Missing/null `/V` stays unsigned; populated values count once across inherited widgets; malformed/unresolved/cyclic/oversized cases stay protected as Unknown. Empty Contents is not an empty field. The app starts protected until a generation/fingerprint-matched reply arrives. Persistent session permission survives transient failure recovery, sheet mutation/drop/undo paths refuse, and a status-bar label remains visible after the warning toast expires. Worker Save/SaveAs/Extract refuse protected inputs before preparation. Hydration, viewing, search and transient printing remain available.

Distinct SaveAs and extraction now capture the shared `output_safety::inspect_destination()` guard before preparation, validate the output before publication and commit through its exact-byte/identity rechecks. Exact/canonical same-source SaveAs retains ordinary `commit_save()` source-conflict checks with no extra destination parse; hard-link-only aliases are rejected by the export guard. Ordinary Save has no additional parse/native call. Overlay/helper behavior and its independent tests belong to the backend owner.

This remains discovery/protection, not signing, certification, integrity/trust verification or proof that malformed/unsupported signatures are absent. Zero native hints can still miss malformed/historical structures. The first milestone does not add same-generation source-revision fields to write requests. Shared output guards narrow races, not filesystem compare-and-swap; conservative destination refusals can reject unsigned PDFs with ambiguous history. The stages below include proposals beyond this bounded milestone.

Checks: initial `cargo check -j2` and focused app/session/arrangement/domain suites passed. After the hinted-value/output-hook correction, `cargo test -j2 --locked --lib worker::` passed 8 tests and `cargo test -j2 --locked --test save_as --test extract` passed both integration tests. Subsequent review added final pre-replace routing rechecks, refusal of populated unknown-kind fields, focused regressions, and a shared quantities test-fixture discovery reply; those latest changes await the coordinated rerun. Independently owned `signature_safety` acceptance is tracked by sig-tests; initial count-only runs failed empty-field expectations and are not acceptance evidence. The vendored wrapper's unit test could not be run as a dependency package outside the workspace. No interactive UI validation was performed.

## Findings backed by source

| Path/interface | Signed-byte hazard |
| --- | --- |
| `src/annots.rs:258`, `save()` | Always reloads the source, calls `apply()`, then `doc.save_to_bytes()`, **even for `Changes::default()`**. The vendored `PdfDocument::save_to_writer()` (`vendor/pdfium-render/src/pdf/document.rs:328`) uses flags `0`, not an incremental-preservation contract. Serialization may change signed bytes, offsets, xref/trailer and prior revisions. A successful PDFium reload proves readability, not signature preservation. |
| `src/markup.rs:130`, `append()`; `src/pins.rs:53`, `append()`; `crates/pdf-io/src/write.rs:104`, `append()` | These use lopdf incremental updates. The measurement writer starts from `IncrementalDocument::create_from(bytes, previous)` and clones changed page/catalog objects into the update. Prefix preservation here cannot repair the preceding PDFium rewrite. Even a genuinely prefix-preserving update can violate DocMDP/FieldMDP or alter what the current document displays. |
| `src/worker.rs:1129`, `with_pages_prepared()` | Blank-page insertion and Cut/Erase load with lopdf, edit content, prune objects and fully `save_to()` before annotation writing. Erasure is content modification, not safe annotation-only editing, and incremental deletion would leave the old drawing recoverable. |
| `src/worker.rs:1196`, `rearranged_bytes()`; `src/arrange.rs:499`, `rearrange()` | Reorder/delete/duplicate/rotate/blank-page operations change the page tree and serialize the whole PDF. Arrangement has separate undo; a session-only guard is insufficient. |
| `src/worker.rs:819`, Save/SaveAs dispatch | Both paths traverse the same rewriting pipeline. Save As protects the old source only when the destination is genuinely different; its output is **not** a signature-preserving copy. Same-path/canonical-alias Save As is an overwrite. |
| `src/worker.rs:1155`, `extract_pages_to()` | Runs preparation, annotation save, rearrangement, reference removal and pruning, then full serialization. It refuses the original/canonical-equivalent target, but retained form/signature dictionaries can misleadingly survive in the derivative with invalid byte ranges. |
| `src/worker.rs:1208`, `print_snapshot()`; `src/printing.rs:296`, `without_markups()` | Print preview/spooling creates rewritten temporary bytes, including rearrangement and optional annotation removal. This does not itself overwrite the source. Printed appearance is not a digital signature or certified PDF; virtual-PDF-printer output is a new document. |
| `src/app/compare.rs:591`, `Compare::generate()`; `src/overlay.rs:254`, `write_aligned()` | Compare reads paths independently, not the main immutable snapshot. Overlay generation creates a new catalog/pages, recolors imported content, then calls `written.save(out)` directly. There is no source-alias rejection or atomic replacement here. Choosing either input as output can destroy it, signed or unsigned. |

`src/app/quantities.rs:561` merely changes markup author metadata (`signed` is a local variable); it is not cryptographic signing. No native signing/provider abstraction was found in `src/` or `crates/`.

Existing guarantees to retain:

- `src/document.rs`, `Snapshot::{new,bytes,file}`: immutable bytes shared by readers. Generation identifies an open document, **not** its successive saves.
- `src/worker.rs:1223`, `commit_save()`: compare source bytes for same-file saves, prepare/reload before commit, recheck immediately before replacement. `write_atomically()` uses a sibling temporary file and rename. Do not bypass either for signing or exact-copy saves. These checks narrow races; they are not an OS file lock or a filesystem identity/compare-and-swap primitive.
- `src/app/mod.rs:808,1088`: ordinary saves allow subsequent session edits and reconcile through `Session::saved()`; structural saves block edits and reopen under a fresh generation. Preserve both behaviors for unsigned files.

## Original synchronous discovery audit (superseded by deferred follow-up)

The count-only absence assumption below is historical: checked form-category discovery is also required at native count zero, because native signature enumeration misses nested/inherited fields. See the current follow-up above.

In `src/worker.rs`, `Request::Open` inspects the already-loaded, unmodified PDFium document before publishing it. One checked native `FPDF_GetSignatureCount` call is the hint; zero takes no extra parser path, while positive hints require bounded AcroForm value inspection. The final policy is retained beside `Loaded::snapshot` and sent through the sibling `Reply::SignatureDiscovery { generation: u64, file: u64, discovery: SignatureDiscovery }` immediately after `Opened`. The UI starts locked until that reply matches its generation/fingerprint. Never discover from the display document after `Loaded::prepare()` strips annotations. The initial count-only/Opened-field proposal was superseded by this tested design.

Available wrappers:

- `doc.signatures().len()` / `.is_empty()` already call `FPDF_GetSignatureCount` (`vendor/pdfium-render/src/pdf/document/signatures.rs`). **Nonzero is only a field hint, not enough to distinguish empty fields from signed values.** Actual tests found native count 1 for missing `/V`, null `/V`, and populated `/V`. The production patch inspects values only on this hinted path; no CMS contents/reasons/timestamps are fetched on the native-zero fast path.
- **Wrapper defect relevant to a safety gate:** `len()` casts native `c_int` to `u16`. Native `-1` means failure (`bindings.rs:1317`), becomes 65535, and large counts can wrap to zero. `iter()` is also unsuitable for fail-closed enumeration: retrieval errors terminate iteration. Do not use iteration success as proof of absence.
- Implemented dependency interface: checked `PdfSignatures::count() -> Result<usize, PdfiumError>` retains native errors without changing existing `len()`. The document handle remains crate-private. The narrow wrapper patch and its documentation are in `vendor/pdfium-render/src/pdf/document/signatures.rs` and `vendor/pdfium-render/PATCHES.md`; the original audit's no-dependency-edits statement applied only before implementation.
- Optional later details: `PdfSignature::modification_detection_permission()` wraps DocMDP; `0` maps to an error, not permission to edit. Contents are CMS/PKCS#1 data, not verification results. ByteRange/SubFilter bindings exist (`bindings.rs:1362–1402`) but have no equivalent high-level accessors in `signature.rs`.

**Unsigned fields are not signatures, but PDFium counts them.** `/FT /Sig` with absent/null `/V` is an empty signing field, not evidence that the document has been signed. A populated signature value, including invalid/unsupported/empty-content signature dictionaries, must not be treated as an ordinary empty field. The native count is field-discovery evidence; the reported `Present.count` instead counts populated values resolved by the hinted inspection. Neither establishes valid cryptography, trusted identity, certification, current-revision coverage or allowed modification classes.

**Boundary of this cheap probe:** a successful native zero means “PDFium found no signature fields,” not “every malformed/unsupported PDF is proven unsigned.” PDFium may repair or omit malformed structures. This audit does not establish its behavior for every broken `/V`, `/Perms`, orphan signature, encrypted file or unsupported signature encoding. Missing discovery support, negative count or explicit parsing failure must produce `Unknown`, never unsigned. Do not market the first patch as complete hostile-input validation. Universal fail-closed structural analysis and literally unchanged zero-parse unsigned saves cannot both be promised; resolve that boundary explicitly rather than hiding a full lopdf parse in `Open`.

## Initial implementation handoff (historical proposals)

The ownership/tasks below preserve the initial handoff, not current API guidance. In particular, the initial assumption “nonzero is enough to lock” was incorrect: tests found native count 1 for missing, null and populated `/V`; only hinted structural inspection distinguishes them. The implemented sibling reply and checked wrapper are described above. `Opened`/`Saved` fields and write-request revision fields proposed below were not added.

The final policy API is `SignatureDiscovery::{NoSignaturesDetected, Present { count: usize }, Unknown}`; neither the state nor the native hint implies validation or absence proof. `Present` and `Unknown` are read-only regardless of DocMDP permission. No “valid/invalid” badge until verification exists.

1. **Domain/protocol/worker owner**
   - `src/domain.rs`: discovery value, pure `allows_document_mutation()` policy; add `Changes::is_empty()` covering **pins, adds, markups, deletes, edits, scales, layers, measures written/removed, erasures**, ignoring author. `Changes::pages()` is not an emptiness check: it omits several categories.
   - `src/protocol.rs`: extend `Reply::Opened` with discovery; carry revision-bound discovery in `Reply::Saved` when a new revision is published. Add expected source fingerprint/revision to write requests if accepting delayed writes; validate it against `Loaded::snapshot` **as well as generation** before preparation. Do not send PDFium handles across channels.
   - `src/worker.rs`: retain discovery with each `Loaded` revision; guard Save, SaveAs and ExtractPages **before** `with_pages_prepared()` or `annots::save()`. For the first patch reject these operations for `Present`/`Unknown`, including clean SaveAs. Leave the `NoSignaturesDetected` pipeline unchanged. Fail using existing replies; no `SaveTarget`, cache rekey, snapshot change or file creation on refusal.
   - Do not silently exempt SaveAs, extraction, scales, layers, pins or author edits. Direct worker requests must be checked even if the UI is disabled. A reusable worker policy function should cover derivative/export intent separately from persistent mutations.
   - Protect the **destination**, too: an unsigned source must not overwrite an existing signed/unknown PDF through SaveAs, extraction or overlay export. For an existing distinct PDF target, probe its exact bytes off the UI thread and refuse protected/unknown replacement; capture and recheck those bytes immediately before rename. This extra load is only for replacement exports, not ordinary unsigned saves. Dialog overwrite confirmation is not a signature-safety check. Reject same-file hard-link aliases using file identity, beyond current canonicalization; consolidate these checks in a shared commit/output helper.
   - Recompute/attach discovery from the prepared document before publishing a committed revision (never from stripped `l.doc`). Future signing and async discovery replies need `(generation, source revision, operation id)` checks. A cache fingerprint is a routing token, not a cryptographic signing identity: retain exact snapshot bytes and use a cryptographic digest in signing transactions.
2. **Session/UI owner**
   - `src/session.rs`: separate persistent document permission from transient `editing_blocked`. Make `can_edit`, `apply`, `apply_merged`, `undo`, `redo`, active-layer mutation and `begin_save` honor both. Keep `load_*` hydration working. `block_editing(false)` must not remove signature protection.
   - `src/app/mod.rs`: add policy to `Doc`, initialize it on `Opened`, retain it across save/reload/failure, reject `save_to()` before `begin_save()` sets pending reconciliation state. Audit Fatal, send failure and `SaveFailed` paths: they currently call `block_editing(false)` independently of a persistent policy.
   - `src/app/palette.rs`, `src/app/files.rs`: disable mutating tools/Save/SaveAs with a clear reason; leave navigation, search, selection, CSV, viewing and compare available. Native method guards are required; `run_action()` itself does not universally enforce `action_enabled()`.
   - `src/app/arrange.rs`: guard `sheets_mut`, drag/drop, `act_on_sheets`, `undo_sheets`, blank-insert confirmation and extraction dispatch. Preserve nonmutating sheet selection/copy. `src/app/lifecycle.rs` should continue to describe transient operations, not become the persistent security state.
3. **Export-safety owner**
   - For patch one block extraction of protected inputs rather than shipping a purportedly signed derivative. Later permit explicit **unsigned derivative** export only after removing certification/signature claims and explaining the loss; never modify the source.
   - `src/overlay.rs::write_aligned` and `src/app/compare.rs::generate`: reject aliases of **either** input before any output, then use atomic output. Shared helper should consider Windows case/normalization, symlinks/junctions and existing hard-link identity; canonicalization alone does not detect hard links. This is a separate overwrite bug, not solved by the main worker's signature lock.
   - Keep preview/printing available: allow transformations only in throwaway bytes, never route them back through a persistent Save. UI wording must distinguish a printed signature appearance from cryptographic proof. If the shared guard is put in `annots::save()`, introduce an explicit transient-derivative intent so print is not accidentally disabled.

Minimal patch touches: `src/{domain,protocol,worker,session}.rs`, `src/app/{mod,palette,files,arrange}.rs`, the checked-count wrapper + its patch note, and focused tests. `src/app/lifecycle.rs` needs review, not necessarily an edit. `src/annots.rs`, the incremental writers and `src/arrange.rs` need no algorithm changes for this lock-only patch. Assign overlay output safety separately; it must not be forgotten because it bypasses worker saves.

Optional subsequent exact-copy feature: a distinct `SaveCopyOriginal` request copies `snapshot.bytes()` unchanged, accepts no pending edits/arrangement and does not masquerade as `annots::save()`. Use revision checks and atomic writing, reject source aliases, and do not switch the active path until a defined successful transition. Warn that unknown/invalid signatures remain unknown/invalid. A different destination may itself contain a signed PDF; require explicit overwrite consent or a no-clobber copy policy rather than assuming destination safety from the source probe.

## Stages after the lock (genuine signing/certification)

- **Structural inventory/verification:** portable core operating on exact immutable bytes; resolve inherited/indirect AcroForm fields, signature `/V`, catalog `/Perms /DocMDP`, signature `/Reference` transforms and FieldMDP/locks. Detect contradictions, cycles, unsupported transforms, invalid ranges and appended revisions. Validate ByteRange lengths/offset arithmetic, ordering, overlap, file bounds and excluded Contents region; verify CMS over precisely those ranges. Distinguish integrity, later modifications, certification policy, identity trust, revocation and trusted timestamp. Unknown cases stay locked. Run expensive analysis off the UI thread; reuse parsing where possible. Add strict pre-write inventory if the product requires protection beyond PDFium-recognized signatures, accepting its cost rather than weakening the guarantee.
- **Portable native signing transaction:** separate UI-independent crate/API, e.g. `prepare(snapshot, field, appearance, certification_policy) -> PreparedSignature`, `complete(prepared, cms) -> SignedCandidate`. Append only to the exact source prefix; reserve fixed-width ByteRange/Contents, finalize offsets and appearance before hashing, fill only the reserved hole, reject oversized CMS and restart preparation with a larger reservation. No PDFium/full lopdf serialization after digesting. Independently reload/verify the candidate and unchanged prefix/ranges before atomic commit. Certification has catalog/transform semantics; a visible stamp or approval signature alone is not certification.
- **Provider adapters:** core owns PDF layout, ranges, CMS profile/verification and policy; adapters expose identity/certificate chain, algorithm capabilities, consent and signing operations (clearly specify digest vs message input). Windows certificate store/CNG, PKCS#11 and remote services are adapters, not the portable PDF core. Keep keys out of document/session state; support cancellation, errors and bounded responses. No platform handle or network I/O in markup-model/UI domain types. Do not assume provider success establishes PDF validity or trust.
- **Transaction/lifecycle:** freeze edits and arrangement for signing; bind result to exact source snapshot + cryptographic digest + operation id. Cancellation, reopen, external change, provider delay or stale response cannot commit. After successful replacement publish a new immutable snapshot/protection state and reopen/rekey readers as for structural saves. Keep old bytes, path, undo and dirty work intact on failure. Apply existing external-change checks immediately before atomic replacement, including same-file aliases. Multi-signature/co-signing and permitted post-certification edits are later features, not inferred from a DocMDP integer.

## Targeted tests / acceptance gates

- New `tests/signature_safety.rs` using `tests/common` worker helpers: normal unsigned PDF, empty signature field, populated signature, certified P=1/2/3, multiple signatures and an appended revision. Assert discovery arrives with `Opened`; signed/certified inputs lock even when cryptographically invalid or unsupported. Include one independently verifiable real signed fixture; synthetic `/Sig` dictionaries test detection only.
- Inject count failure/overflow in wrapper/policy unit tests; malformed `/V`, broken `/Perms`, missing/empty Contents, unsupported SubFilter, encrypted/failed open and structural ambiguity must have documented outcomes, not accidental unsigned promotion. Assert the known PDFium-zero limitation explicitly until strict inventory lands.
- Direct Save/SaveAs (same path, alias and distinct target), arrangement-only, new-page, pins-only, scales/layers-only, measurement edit/removal, note/author edit and erasure requests: rejected before writer/temp-file creation for protected inputs; source, existing target, Loaded revision/path, cache and session remain unchanged. Extraction also refuses. Include unsigned source → signed/unknown existing target, target changed during preparation, hard-link aliases, stale generation and same-generation stale-revision requests.
- Session/UI unit tests: commands/merged edits/undo/redo/`begin_save` and every sheet mutation blocked; hydration/selection/search still work. A failed save or `block_editing(false)` cannot unlock. Interactive check disabled tools, direct shortcuts, context menus, insert dialog, drag/drop, clear warning, printing and compare.
- Extend overlay tests: output equals either input, symlink/case alias and Windows hard link; both source bytes survive rejection/failure. Explicit derivative tests must not retain certification claims.
- Re-run `tests/{save_as,extract,printing,document_revision,helper_revision,arrange_cache}.rs`, session save-during-edit tests and worker `save_tests::{failed_preparation_keeps_original_and_allows_retry,external_change_during_preparation_is_preserved}`. Add external source change before/during copy/sign preparation and injected temp/rename/provider/reload failures.
- Signing stages: independently verify CMS/ranges and prefix equality; wrong digest, tampered byte, trailing revision, malformed/overflowing ranges, underestimated Contents, unsupported algorithm, canceled/stale provider response, source changed on disk, certification/field-lock violation and multiple-signature ordering. Validity tests must use a verifier independent of the signer.
